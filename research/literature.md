# Literature notes (routing research loop)

Leads and primary sources reviewed at night. "Fit" = what it means for Via.

| Topic | Source | Claim (as stated by source) | Fit for Via |
| --- | --- | --- | --- |
| Common lines / attractive sets | Chriqui & Robillard 1975; Spiess & Florian 1989; Cominetti & Correa 2001 ([PDF](https://www.dii.uchile.cl/~jcorrea/papers/Journals/CC2001.pdf)) | A rider at a stop picks a set of attractive lines and boards the first one that arrives | Basis of EXP-008: widen each transit edge to every line between the same pair of places, so Phase 2 boards the first predicted bus |
| ULTRA | Baum, Buchhold, Sauer, Wagner, Zündorf, ULTRA ([arXiv 1906.04832](https://arxiv.org/abs/1906.04832); Transportation Science 2023); code [kit-algo/ULTRA](https://www.github.com/kit-algo/ULTRA) | Preprocessing computes a small set of transfer shortcuts, so RAPTOR/CSA handle unlimited walking or bike transfers without slower queries | B11: bike-share shortcuts. Via's BikeShare is in Phase 2 with request-time availability, so shortcuts would only help Phase 1 discovery. Medium cost; not yet prototyped |
| Bike availability forecasting | Feng, Hillston & Reijsbergen 2016 (moment-based probabilistic prediction, [PDF](https://www.pure.ed.ac.uk/ws/files/25345632/Feng_et_al_2016_Moment_Based_Probablitstic_Prediction.pdf)); Ashqar et al. ([arXiv 2006.08352](https://arxiv.org/pdf/2006.08352)); SAFEBIKE ([arXiv 1712.01469](https://arxiv.org/pdf/1712.01469)) | Short-horizon forecasts (10–30 min) beat persistence. Full distributions beat time-inhomogeneous queue models. A 15 min horizon gave the lowest error in a Bay Area study | Via uses current YouBike availability at the pickup time. A forecast would matter for drop-off docks reached 20+ min later. Needs a history of availability snapshots, which Via does not keep |
| MOTIS / Transitous | [motis-project/motis](https://github.com/motis-project/motis), [Transitous docs](https://transitous.org/doc/) | Multiple GTFS + GTFS-RT + GBFS. RT polled about once a minute | No TDX feed equivalent; nothing directly reusable found tonight |
| OTP station transfers | OTP docs ([v1.5 config](https://docs.opentripplanner.org/en/v1.5.0/Configuration/)): `stationTransfers`, `stopClusterMode` (proximity+name or parent station) | Stops are grouped by name and proximity for transfers and search | Same grouping rule as Via's place (same name, ≤100 m, EXP-002/008) |
